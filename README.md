# YT-AutoCaptions

Мини-приложение для загрузки видео и шортсов на YouTube.

**Стек:** Python 3.14 · PyQt6 · YouTube Data API v3 · OAuth2

## Возможности

- 🌑 Тёмная тема (единый QSS-стиль, акцент — фирменный красный YouTube).
- Четыре вкладки: **«🎬 Видео»**, **«⚡ Шортсы»**, **«💬 Субтитры»** и **«🎵 Убрать музыку»**.
- Простая загрузка: **нажал кнопку → выбрал файл** → название подставится из имени.
- **Авто-шаблон для аниме-шортсов**: введи `название аниме` и `озвучку` — приложение
  само составит название (`«Название» — нарезка | Озвучка`), красивое описание
  (с сайтом `vilibrity.ru` и телеграмом) и теги с автодублированием на русский/английский.
  Всё остаётся редактируемым перед загрузкой.
- **Вкладка «Субтитры»**: выбираешь видео → показывается примерное время работы →
  распознаётся речь → встраиваются karaoke-субтитры по центру (текущее слово — жёлтым,
  остальные — белым). Модель, язык и шрифт настраиваются.
- **🎵 Вкладка «Убрать музыку»**: выбираешь видео → Demucs убирает музыку/саундтрек,
  оставляя голос/озвучку, результат — `..._vocals.mp4`. Снижает риск бана за авторские
  права на музыку. Тот же чекбокс есть и в загрузке (Видео/Шортсы).
- Поля: название, описание, теги, категория, видимость (приватно/не перечислено/публично),
  превью (thumbnail), «для детей».
- Прогресс загрузки в фоне (не блокирует UI) + итоговая ссылка на видео.
- OAuth2-авторизация через `client_secret_*.json`, refresh-токен сохраняется в `token.json`.
- Корректное закрытие по крестику: фоновые потоки останавливаются, окно не зависает.

## Установка

```bash
# Виртуальное окружение уже создано (venv), просто ставим зависимости:
venv/bin/pip install -r requirements.txt

# (опционально) автоматическое определение длительности шортсов через ffprobe:
#   apt install ffmpeg

# ⚙️ Конфигурация: создайте свой .env из шаблона и впишите реальные ключи
#    (получаются в Google Cloud Console → APIs & Services → Credentials)
cp .env.example .env
```

> **Важно:** после клонирования репозитория обязательно положите рядом файл
> `client_secret_<client_id>.json` (скачивается в Google Cloud Console →
> раздел «Credentials» → Create OAuth client ID → Desktop app) — без него не
> заработает OAuth-авторизация. Эти файлы и `.env` не хранятся в git (см.
> `.gitignore`) — их нужно держать локально и никогда не публиковать.

## Запуск

```bash
venv/bin/python main.py
```

## Auto Caption (субтитры в видео)

Распознаёт речь и **красиво встраивает karaoke-субтитры прямо в видео**:
- слово, произносимое **сейчас** — **жёлтым**,
- остальные слова строки — **белыми**,
- текст **по центру**, с обводкой; длинные строки автоматически разбиваются,
  чтобы не вылезать за края.

Доступен двумя способами:

**1. В приложении** — вкладка **«💬 Субтитры»**: выбери видео → увидишь примерное
время работы → «Создать субтитры». Модель, язык и размер шрифта настраиваются.

**2. Отдельным скриптом** `subtitle_tool.py`:

```bash
# все зависимости (включая faster-whisper, onnxruntime, demucs) ставятся одной командой:
venv/bin/pip install -r requirements.txt

# базово
venv/bin/python subtitle_tool.py my_video.mp4

# точнее + русский
venv/bin/python subtitle_tool.py my_video.mp4 --model small --lang ru --keep
```

Параметры:

| Флаг | Описание |
|------|----------|
| `--model {tiny,base,small,medium}` | Точность/скорость. `small` — хороший баланс |
| `--lang ru/en/ja…` | Язык (по умолчанию ru; пустое = автоопределение) |
| `-o ФАЙЛ` | Выходной файл (по умолчанию `<видео>_captioned.mp4`) |
| `--font / --font-size` | Шрифт и размер субтитров |
| `--keep` | Сохранить промежуточный `subs.ass` рядом с результатом |

Точность: используется `word_timestamps=True` — каждое слово получает точный
таймкод, поэтому жёлтая подсветка совпадает со звуком. Модель скачивается один
раз при первом запуске. Нужен установленный `ffmpeg`.

## Удаление музыки (Demucs)

Есть вкладка **«🎵 Убрать музыку»** и чекбокс **«Убрать музыку (оставить голос
и эффекты)»** во вкладках «Видео»/«Шортсы». Видео прогоняется через **Demucs
(`htdemucs_6s`)** — разделение на 6 стемов:

- **остаются**: `vocals` (голос/озвучка), `other` (эффекты: шаги, шелест, скрипы),
  `drums` (ударные/стуки) — чтобы сохранить звуковые эффекты;
- **убираются**: `bass`, `guitar`, `piano` — явная музыка.

Баланс настроен так, чтобы максимально сохранять эффекты, даже если лёгкий
музыкальный фон останется. Это заметно снижает риск бана за авторские права
на музыку/саундтрек.

Требуется: `demucs` + `torch` (ставятся через `venv/bin/pip install -r requirements.txt`). У тебя есть
RTX 3060 — демucs автоматически использует CUDA (быстро); при желании можно
собрать и CUDA-версию torch через `pip install torch torchaudio --index-url
https://download.pytorch.org/whl/cu126`.

## Авторизация

Перед первой загрузкой нажмите **Приложение → 🔑 Авторизация в YouTube**.
Откроется браузер — подтвердите доступ. Токен сохранится в `token.json`
(создаётся автоматически в корне проекта) и не будет запрошен повторно.

## Настройка шаблона шортсов

Вкладка **«Шортсы»** автоматически заполняет название, описание и теги, исходя
из полей ввода. Шаблон полностью настраивается — **под любой формат контента**
(аниме, реакции, обзоры, гайды и т.п.): вы сами задаёте количество полей ввода,
их подписи и текст, в который они подставляются.

**Способ 1 — файл-шаблон (полный контроль)**

```bash
cp shorts_template.txt.example shorts_template.txt
```

Откройте `shorts_template.txt` и отредактируйте секции: файл **подхватится
автоматически** (приложение ищет `shorts_template.txt` в корне проекта). Если хотите
указать другой путь — пропишите в `.env`:

```ini
SHORTS_TEMPLATE_FILE=shorts_template.txt
```

| Секция | Назначение |
|--------|-----------|
| `FIELDS:` | Поля ввода, которые появятся в приложении. Каждая строка: `ключ | Подпись | Подсказка-пример`. Ключ = плейсхолдер `{ключ}` ниже |
| `TITLE:` | Шаблон названия шортса (можно 1–2 строки) |
| `DESCRIPTION:` | Описание — каждая строка файла станет строкой описания (пустая строка = пустая строка) |
| `TAGS:` | Теги через запятую (по строке/по столбцу) |

Пример — **произвольный набор полей** (например для обзоров):

```text
FIELDS:
название | Название ролика | Например: Итоги месяца
гость    | Гость          | Кто будет смотреть
ссылка   | Ссылка на оригинал |

TITLE:
{название} с {гость}

DESCRIPTION:
Обзор: {название}
В гостях: {гость}
Ссылка: {ссылка}

Подписывайтесь! {tags}

TAGS:
обзор, разбор, летсплей, обсуждение
```

Встроенные плейсхолдеры (добавляются автоматически):

| Плейсхолдер | Что подставляется |
|-------------|-------------------|
| `{имя_поля}` | Значение соответствующего поля из секции `FIELDS` |
| `{site}`    | Ваш сайт из `.env` (`SHORTS_SITE_URL`) |
| `{tg}`      | Ваш телеграм из `.env` (`SHORTS_TG_URL`) |
| `{tags}`    | Теги из секции `TAGS`, превращённые в хэштеги `#тег1 #тег2` |

> Обычно первое поле используется в названии. Если поле не заполнено,
> `{поле}` подставится пустым — это удобно для необязательных полей.

> Файл `shorts_template.txt` не хранится в git (см. `.gitignore`), поэтому личные
> ссылки и тексты не попадут в открытый репозиторий.

**Способ 2 — только через `.env` (быстро, без файла-шаблона)**

Если `SHORTS_TEMPLATE_FILE` пуст, используются поля по умолчанию
(«название» и «озвучка» — под аниме-нарезки) и переменные `.env`:

```ini
# .env
SHORTS_SITE_URL=ваш-сайт.ру
SHORTS_TG_URL=https://t.me/ваш_канал
SHORTS_BASE_TAGS=аниме, анимешортс, shorts, anime
```


### Как получить Client ID / Client Secret и «разрешить» приложению загружать видео

Эти шаги нужны **один раз** — чтобы приложение могло загружать видео на ваш канал.

**Шаг 1. Откройте Google Cloud Console**

Перейдите на сайт:
👉 **https://console.cloud.google.com/**

Войдите тем Google-аккаунтом, на который хотите загружать видео (это должен быть
владелец/менеджер **вашего канала**).

**Шаг 2. Выберите (или создайте) проект**

- Вверху слева нажмите на выпадающий список **проектов** (рядом с логотипом).
- Выберите нужный проект или создайте новый (**New Project** → задайте имя → **Create**).

**Шаг 3. Включите «YouTube Data API v3»**

- В левом меню откройте **APIs & Services → Library** (или **Библиотека**).
- В строке поиска введите `YouTube Data API`.
- Выберите **«YouTube Data API v3»** → нажмите **Enable** (Включить).

**Шаг 4. Создайте OAuth Client ID (Client ID и Client Secret)**

- В левом меню откройте **APIs & Services → Credentials** (Учётные данные).
- Нажмите **+ Create Credentials** (Создать учетные данные) → **OAuth client ID**.
- Если система попросит настроить «OAuth consent screen» (Экран согласия):
  - нажмите **Configure consent screen**;
  - выберите тип **External** (Внешний) → **Create**;
  - заполните минимум: **App name** (например, `ViVideoYouTube`) и **User support email**;
  - ниже обязательно добавьте свой email в **Developer contact information**;
  - **Save and continue** до конца (разрешения оставьте как есть) → вернётесь к созданию клиента.
- В форме **Create OAuth client ID**:
  - **Application type** → выберите **Desktop app**;
  - **Name** → любое (например, `ViVideoYouTube Desktop`);
  - нажмите **Create**.
- Появится окно с **Client ID** и **Client Secret** — скопируйте их.

**Шаг 5. Скачайте файл `client_secret_*.json`**

- На той же странице **Credentials** в списке клиентов нажмите **скачать**
  (иконка ⬇ / **Download JSON**) у созданного OAuth-клиента.
- Положите скачанный файл в **корень проекта** рядом с `main.py`.

**Шаг 6. Пропишите данные в `token.json`-генерацию через `.env`**

Скопируйте шаблон и впишите свои значения:

```bash
cp .env.example .env
```

```ini
# .env
CLIENT_ID=ваш_client_id
CLIENT_SECRET=ваш_client_secret
CLIENT_SECRET_FILE=client_secret_<ваш_client_id>.json
```

> имена `client_id` и `client_secret` берите из скачанного
> `client_secret_*.json` или из окна «Create OAuth client ID».

**Шаг 7. Добавьте свой аккаунт в тестовые пользователи (обязательно!)**

Приложение обычно в **тестовом режиме** (Testing), поэтому без верификации Google
разрешит доступ только тем аккаунтам, которые добавлены в **Test users**:

1. В Google Cloud Console откройте **APIs & Services → OAuth consent screen**.
2. В разделе **Test users** нажмите **+ Add users**.
3. Впишите email того аккаунта, под которым будете загружать видео.
4. **Save**. Изменения вступают в силу практически сразу.

> Если этого не сделать, при авторизации появится ошибка **403 access_denied**
> или «Access blocked» — просто добавьте аккаунт в Test users и повторите.

**Шаг 8. Авторизуйтесь в приложении**

Запустите приложение и нажмите **Приложение → 🔑 Авторизация в YouTube**.
Откроется браузер → войдите нужным аккаунтом → подтвердите разрешения.
Токен сохранится в `token.json`, и повторно авторизоваться не придётся.

### Куда именно вставить данные — краткая шпаргалка

| Что нужно | Где взять (сайт → меню) |
|-----------|--------------------------|
| Проект | console.cloud.google.com → список проектов (слева вверху) |
| Включить API | **APIs & Services → Library** → `YouTube Data API v3` → **Enable** |
| Client ID / Secret | **APIs & Services → Credentials** → **Create Credentials** → **OAuth client ID** → **Desktop app** |
| Скачать JSON | **APIs & Services → Credentials** → ⬇ у строки клиента |
| Добавить тест-пользователя | **APIs & Services → OAuth consent screen** → **Test users** → **Add users** |

> ⚠️ Client ID / Client Secret — это ваши секретные данные (доступ к проекту).
> Никому их не показывайте и не коммитьте в git (они исключены через
> `.gitignore`).

## Файлы конфигурации

| Файл | Назначение |
|------|-----------|
| `.env.example` | Шаблон настроек (коммитится, без реальных ключей) |
| `.env` | API-ключ, Client ID/Secret, пути, скоупы (НЕ коммитится) |
| `client_secret_*.json` | OAuth-клиент (installed app) для авторизации (НЕ коммитится) |
| `token.json` | Создаётся после первой авторизации (НЕ коммитится) |
| `shorts_template.txt.example` | Пример файла-шаблона шортсов (коммитится) |
| `shorts_template.txt` | Личный файл-шаблон шортсов (НЕ коммитится) |

> ⚠️ Файлы `.env`, `client_secret_*.json`, `token.json` и `shorts_template.txt`
> исключены через `.gitignore`. Храните их только локально и никогда не
> публикуйте и не отправляйте третьим лицам: `client_secret` — это ключ доступа
> к вашему Google Cloud-проекту, `token.json` — реальный авторизационный токен,
> а `shorts_template.txt` может содержать ваши личные ссылки и тексты.

```
├── config.py          # загрузка .env и параметры

    └── music_remover_tab.py # вкладка «Убрать музыку» (Demucs)
```
